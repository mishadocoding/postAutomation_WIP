АВТОМАТИЗАЦИЯ ПУБЛИКАЦИЙ В INSTAGRAM
Руководство для нового пользователя
Русский — 15.11.2026
============================================

1. ЧТО УМЕЕТ ПРОГРАММА

Программа работает на компьютере с Windows и поддерживает два сценария:

А) Публикация готового видео в указанное время.
   Вы предоставляете видео и файл с подписью. Создание видео и проверка
   качества изображения искусственным интеллектом здесь не выполняются.

Б) Создание нового видео по локальному проекту SampleERP с последующей
   проверкой, исправлением и публикацией.
   Для этого нужны Codex и HyperFrames. Видео, не прошедшее проверку,
   автоматически не публикуется. Возможны остановки из-за качества результата.

Автоматическая публикация готового файла через фоновую задачу подтверждена
на практике. Это не означает, что каждое новое видео автоматически создастся
и успешно пройдёт все проверки. Начните со сценария А.

Текст руководства дан на русском языке. Названия файлов, команды, ключи
настроек и идентификаторы состояний сохранены в исходном виде, поскольку
именно такое написание требуется программе.

2. ЧТО НЕОБХОДИМО

- Компьютер с Windows и подключением к интернету.
- Python 3; рядом с ним должен быть установлен pythonw.exe.
- FFmpeg и ffprobe, доступные из PowerShell.
- Git для получения проекта с GitHub.
- Профессиональный аккаунт Instagram, связанный со страницей Facebook.
- Приложение Meta, необходимые разрешения и действующий токен доступа.
- Часовой пояс Windows: Ташкент, UTC+05:00.

Дополнительно только для сценария Б:
- Node.js версии 22 или новее и npm.
- HyperFrames 0.9.39: эта версия закреплена в проекте.
- Программа Codex для командной строки с выполненным входом и доступным лимитом.
- Установленные инструкции HyperFrames для работы с Codex.
- Локальная копия исходного приложения SampleERP.

Для основной части программы на Python дополнительные пакеты pip не нужны.
Доступ к Codex зависит от условий и лимитов вашего аккаунта. Руководство
не обещает неограниченное бесплатное создание видео.

3. ПОЛУЧЕНИЕ ПРОЕКТА И РАБОЧАЯ ПАПКА

Откройте PowerShell под обычной учётной записью Windows. Под ней же
устанавливайте фоновую задачу. Не устанавливайте задачу под ограниченной
служебной учётной записью Codex.

Для новой копии:

  cd "$env:USERPROFILE\Documents"
  git clone https://github.com/mishadocoding/postAutomation_WIP.git postAutomation_WIP
  cd .\postAutomation_WIP\publishing

Если проект уже есть, перейдите в его папку publishing. Пример для текущего
компьютера:

  cd "C:\Users\hadzhee2K\Documents\SampleERP-promo\publishing"

Все дальнейшие команды выполняются из publishing. Пути из примеров
заменяйте путями вашего компьютера.

4. ПОДГОТОВКА META И INSTAGRAM

1) Переведите Instagram в профессиональный режим.
2) Создайте страницу Facebook и свяжите её с Instagram.
3) Создайте приложение разработчика Meta. Эта программа использует вход
   через Facebook; токены другого способа входа сюда не подставляйте.
4) Настройте управление содержимым Instagram и возможность публикации.
5) Предоставьте нужному аккаунту и странице следующие разрешения:

   instagram_basic
   instagram_content_publish
   pages_read_engagement
   pages_show_list
   business_management

Последнее разрешение необходимо при некоторых вариантах владения
страницей и бизнес-активами. Следуйте требованиям вашего приложения Meta.
При работе в режиме разработки у пользователя должна быть соответствующая
роль в приложении. Для обслуживания сторонних аккаунтов Meta может
потребовать дополнительную проверку приложения и разрешений.

6) В инструменте Meta выберите своё приложение и получите токен пользователя.
7) Для поиска страницы и числового идентификатора Instagram выполните запрос:

   me/accounts?fields=id,name,access_token,instagram_business_account{id,username}

Нужное значение — instagram_business_account.id. Это не идентификатор
страницы Facebook и не имя аккаунта с символом @.

Для длительной работы обменяйте токен пользователя на долгосрочный и
получите из него токен страницы. Если инструмент проверки Meta предлагает
кнопку продления, можно воспользоваться ею. Если кнопки нет, попросите
владельца приложения настроить официальный обмен токена. Просроченный
токен сначала необходимо получить заново.

Долгосрочный токен страницы может не иметь фиксированной даты окончания,
но доступ всё равно может быть отозван или ограничен. Не отправляйте
токены, пароли и секрет приложения в переписку и не загружайте их в GitHub.

5. СОХРАНЕНИЕ ТОКЕНА НА КОМПЬЮТЕРЕ

Если .env ещё не существует, создайте его из примера:

  if (-not (Test-Path .env)) { Copy-Item .env.example .env }
  notepad .env

Заполните три значения:

  META_API_VERSION=v27.0
  INSTAGRAM_ACCOUNT_ID=ЧИСЛОВОЙ_ИДЕНТИФИКАТОР_INSTAGRAM
  META_ACCESS_TOKEN=ТОКЕН_СТРАНИЦЫ

Версия API приведена как пример: используйте поддерживаемую версию вашего
приложения Meta. Замените текстовые обозначения настоящими значениями.
Не копируйте пример поверх уже настроенного .env: так можно потерять токен.

Проверьте доступ:

  python .\push_reel.py --check-account

Должны появиться имя вашего аккаунта и данные квоты публикаций. Команда
не загружает видео и ничего не публикует. Успешная проверка аккаунта
не гарантирует принятие любого конкретного видео.

Если переменные META_ уже заданы в окружении Windows, они имеют приоритет
над .env. Старый токен в окружении может объяснять различия между запусками;
попросите специалиста проверить настройки, не раскрывая сам токен.

6. ПЕРВИЧНЫЕ НАСТРОЙКИ

На новом компьютере сначала откройте schedule.json и установите:

  "maintenance": true

Это удерживает новые запуски и окончательную публикацию. Уже запущенное
создание видео при этом не обязательно завершится немедленно.

Основные параметры schedule.json:

  daily_time        — ежедневное время публикации, например "18:00".
  utc_offset        — "+05:00"; текущая реализация рассчитана на Ташкент.
  prepare_minutes   — начало подготовки заранее; сейчас 50 минут.
  poll_minutes      — интервал проверки расписания; сейчас 2 минуты.
  catch_up_minutes  — разрешённое окно опоздания; сейчас 60 минут.
  notifications    — true для местных уведомлений Windows.
  mode             — "generate" для автоматического создания видео.
  sample_slots     — разовые запуски создания с полной датой и временем.
  excluded_slots   — конкретные моменты, которые нужно пропустить.
  run_aliases      — техническое сопоставление с существующими записями работ.

На новой установке ненужные старые испытательные даты можно убрать:
sample_slots и excluded_slots сделать [], а run_aliases — {}. Не заменяйте
действующее расписание другой машины примерами без проверки.

Важно: задания, добавленные через schedule-file, хранятся отдельно в базе.
Изменение sample_slots не отменяет такие публикации.

Если нужен только сценарий А и у вас нет SampleERP, установите enabled=false
в project_source.json, сохранив mode="generate" и poll_minutes=2 в
schedule.json. Не добавляйте в briefs задания создания на конкретные даты.
Готовые файлы будут регулярно проверяться по времени, а задание на создание
видео искусственному интеллекту не поступит. При mode="queue" установщик
создаёт другой, ежедневный режим запуска: не выбирайте его для проверки
разовых времён каждые две минуты.

7. ПУБЛИКАЦИЯ ГОТОВОГО ВИДЕО ПО РАСПИСАНИЮ

Подготовьте MP4 или MOV и обычный текстовый файл подписи в кодировке UTF-8.
Подпись должна содержать от 1 до 2200 символов. В примере файлы называются
gotovoe_video.mp4 и podpis.txt и находятся в publishing.

Чтобы назначить публикацию через 10 минут:

  $postAt = (Get-Date).AddMinutes(10).ToString("yyyy-MM-ddTHH:mm:sszzz")
  python .\automation.py schedule-file --video .\gotovoe_video.mp4 --caption-file .\podpis.txt --at $postAt

Команда пока не публикует: она сохраняет местную копию файлов и время.
Установленная задача Windows сама загрузит и опубликует видео при первом
опросе в назначенное время или после него. Дополнительно запускать
ручную команду --publish не требуется.

Дата должна быть в будущем. Если этот же файл уже опубликован программой
в тот же аккаунт, повторное добавление отклоняется. Разовые публикации
готовых файлов работают вместе с ежедневным созданием видео. При
maintenance=true они тоже удерживаются.

Отдельной команды отмены одной такой публикации сейчас нет. При
необходимости установите maintenance=true, чтобы удержать новые
публикации, и обратитесь к сопровождающему проекта. Не удаляйте базу.

8. УСТАНОВКА И ЗАПУСК ЗАДАЧИ WINDOWS

Перед установкой проверьте часовой пояс Ташкента и доступ к аккаунту.
Когда настройки готовы, установите maintenance=false в schedule.json.

Предварительный просмотр настроек без установки:

  python .\install_task.py

Установка или обновление подходящей задачи текущего пользователя с запуском:

  python .\install_task.py --install --update --start

ВНИМАНИЕ: вторая команда запускает реальную работу. Если время публикации
уже наступило, программа может загрузить и опубликовать видео.

Имя задачи: PostAutomation-Instagram.
Окно PowerShell после установки можно закрыть. Оставайтесь в своей
учётной записи Windows, оставьте компьютер включённым, без перехода в сон,
и обеспечьте интернет. Задача работает без прав администратора.
До переноса на другой работающий компьютер или сервер выключенный
компьютер не сможет выполнять публикации.

Посмотреть состояние задачи:

  schtasks /Query /TN "PostAutomation-Instagram" /V /FO LIST

Программа объединяет повторные вызовы в одном интервале. Если обнаружены
лишние копии задач, попросите сопровождающего проверить и убрать их.

9. НАСТРОЙКА АВТОМАТИЧЕСКОГО СОЗДАНИЯ ВИДЕО

Раздел нужен только для сценария Б. Для публикации готового файла
Codex, Node.js и HyperFrames не требуются.

Проверьте инструменты:

  python --version
  node --version
  ffmpeg -version
  ffprobe -version
  codex --version

Ссылка на установку Codex приведена в разделе 15. Войдите в аккаунт:

  codex login
  codex login status

Загрузите закреплённую версию HyperFrames и установите инструкции:

  npx --yes hyperframes@0.9.39 --version
  npx --yes hyperframes@0.9.39 skills update

Версия Node.js, используемая самим PowerShell, также должна быть не ниже 22.
После установки новых инструкций начните новый процесс Codex.

В generation.json укажите путь к вашему node.exe в node_executable.
Узнать путь можно командой:

  (Get-Command node).Source

В project_source.json настройте:
- project_path: полный путь к исходному приложению SampleERP.
- enabled: true для автоматического составления задания по локальному проекту.
- language: язык текста видео; например "Русский".
- topics: список допустимых тем.

Приложение SampleERP не входит в этот репозиторий; получите его отдельно.
Сохраняйте изменения в файлах. Программа читает сохранённую рабочую копию,
включая изменения, ещё не внесённые в Git, но сама не получает новую
версию из удалённого репозитория.

Проверьте готовность:

  python .\generation.py doctor

Если отсутствует необходимый браузер:

  npx --yes hyperframes@0.9.39 browser ensure

Полная проба без публикации:

  $testDate = (Get-Date).AddDays(1).ToString("yyyy-MM-dd")
  python .\generation.py test --date $testDate

Выполняются создание, технические проверки, выпуск видеофайла и независимая
визуальная проверка. Загрузки и публикации в Instagram не будет. Состояние
reviewed означает успешное прохождение критериев. Уже успешно завершённая
проба на ту же дату может не запускать создание заново.

После осознанного ручного исправления существующего пробного проекта:

  python .\generation.py recheck --date $testDate

Эта команда тоже не публикует и не меняет maintenance. Она повторно
проверяет и выпускает существующий проект без повторного запуска автора Codex.

10. КАК ПРОХОДИТ ЕЖЕДНЕВНАЯ РАБОТА

При daily_time=18:00 и prepare_minutes=50 подготовка разрешена с 17:10.
Проверка расписания выполняется каждые 2 минуты. Видео создаётся на основе
актуальных фактов из проекта. При проблемах с технической или визуальной
проверкой выполняется не более трёх попыток.

Если исходный проект изменился, публикация устаревшего видео может быть
удержана. Программа намеренно не публикует раньше назначенного времени.
Публикация в точную секунду не гарантируется: создание, проверки, интернет
и обработка Meta занимают время. По завершении окна опоздания работа
может остаться для ручного разбора.

Тема может повторяться. Есть проверки одинаковых и визуально близких
видео, но абсолютной гарантии смысловой уникальности нет. Следите за
результатами, особенно при первых автоматических запусках.

11. СОСТОЯНИЕ, ЖУРНАЛЫ И УВЕДОМЛЕНИЯ

  python .\automation.py status
  python .\automation.py run

Вторая команда лишь показывает подходящие интервалы и не запускает
настоящую генерацию или публикацию.

Последние строки сегодняшнего журнала:

  $day = Get-Date -Format yyyy-MM-dd
  Get-Content ".\.state\automation\logs\$day.log" -Tail 60

Основные состояния:
  queued          — файл ожидает своего времени.
  assigned        — передан рабочему процессу или ожидает повторной попытки.
  generating      — идёт создание или проверка.
  reviewed        — проба без публикации успешно завершена.
  approved        — проверки пройдены; это ещё не подтверждение публикации.
  published       — Meta подтвердила публикацию.
  needs_attention — автоматическое продолжение остановлено; изучите причину.

При успехе или остановке показывается уведомление Windows. Системные
настройки уведомлений могут скрыть его. Проверка уведомления:

  python .\notifications.py --test

События: .state\notifications\events.jsonl.
Доказательства проверок: папки дат и попыток в .state\generation\.
История публикаций: .state\posts.sqlite3.
Готовые файлы по расписанию: .state\automation\queue.sqlite3.

Одна ссылка на Instagram не доказывает работу расписания. Для готового
файла сопоставьте время журнала, запись задания и идентификатор
scheduled_file_worker в записи публикации.

12. ИНТЕРНЕТ И ТИПОВЫЕ ОШИБКИ

  python .\network_check.py
  python .\push_reel.py --check-account

Обе команды не публикуют. Первая проверяет соединение с двумя адресами
Meta без передачи токена. Вторая отдельно проверяет действующий доступ
к аккаунту. Ответ 400 или 429 означает, что сервер ответил. Код 429 означает
ограничение частоты запросов; он не подтверждает успешную загрузку видео.
Отчёт сохраняется в .state\network\latest.json.

- 10013 или access_denied: Windows ограничивает сеть для этого процесса.
  Проверьте из обычной учётной записи. Ограничение служебной учётной записи
  Codex само по себе не означает блокировку вашей фоновой задачи.
- 190, в том числе 463: токен может быть просрочен или недействителен.
  Проверьте его, при необходимости замените и повторите проверку аккаунта.
- Пустой список страниц: проверьте наличие страницы, свои полномочия
  на неё и выданные приложению разрешения.
- Нет Instagram ID: проверьте связь профессионального аккаунта со страницей.
- Не найден ffmpeg, ffprobe, node или codex: проверьте установку и доступность
  команды; после изменения путей откройте новый PowerShell.
- needs_attention: прочитайте failure.json, check.json и review.json
  соответствующей попытки. Не удаляйте базу для обхода причины остановки.
- Прервано состояние creating, uploading или publishing: публикация могла
  состояться. Сначала проверьте Instagram и сохранённое состояние;
  не выполняйте повторную публикацию вслепую.

Временные ошибки запросов чтения могут повторяться до трёх раз. Запросы
загрузки и публикации не повторяются вслепую: учитывается сохранённое состояние.

13. ПРИОСТАНОВКА, ВОЗОБНОВЛЕНИЕ И РУЧНАЯ ПУБЛИКАЦИЯ

Для удержания новых работ: maintenance=true в schedule.json.
Для продолжения: maintenance=false. Следующий вызов читает новые настройки.
Все пропущенные старые задания автоматически не воспроизводятся.

Отключить задачу Windows:

  schtasks /Change /TN "PostAutomation-Instagram" /Disable

Включить задачу:

  schtasks /Change /TN "PostAutomation-Instagram" /Enable

Эти команды не завершают уже работающий процесс немедленно.
Принудительный обрыв может оставить результат загрузки или публикации
неопределённым.

Только если вы намеренно хотите немедленную ручную публикацию:

  python .\push_reel.py --video .\gotovoe_video.mp4 --caption-file .\podpis.txt --publish

Это настоящая публикация без ожидания расписания и без визуальной проверки.
Ручной успех не является подтверждением работы задачи Windows.
Не запускайте один файл одновременно вручную и через расписание.

14. ОБНОВЛЕНИЕ И РЕЗЕРВНАЯ КОПИЯ

Сохраните .env и .state в безопасном местном хранилище. Копия с GitHub
не восстанавливает токены, историю публикаций или задачу Windows.
Удаление .state может уничтожить историю защиты от повторной публикации.

Дождитесь завершения активной публикации и установите maintenance=true.
Затем из корневой папки проекта:

  git pull --ff-only

Если мешают местные изменения, не применяйте команды, уничтожающие их.
После обновления проверьте состояние и наличие инструментов.

При переносе в другую папку исправьте пути в project_source.json,
generation.json и в задаче Windows.
